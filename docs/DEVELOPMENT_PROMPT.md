# AI Pulse Agent 开发执行提示词

用户已授权本地开发，环境改用 Conda；先保证本地运行，模型 API 先创建模板，真实接入测试放在最后。后续用户修订优先于本文，具体需求以已确认方案和最新指令为准。

最新产品定位以 PRODUCT_PLAN.md 为准：面向关注 AI 的开发者，行业热点与真实产品案例各最多5条，默认中文阅读3至5分钟，摘要本身完成信息交付。板块独立于网页或仓库类型；单侧不足时少报，不互相补位。排除融资、人事、同质化套壳，调用现成模型本身不作为排除条件。热点讲变化与意义，案例讲人群、问题、用法与新意；不生成虚构产品点子。原文点击不作为推荐价值的主要指标。

## 项目任务

在 `E:\ai-pulse-agent` 开发一个 Windows 本地运行、单用户使用的 AI 信息变化追踪 Agent。采用 Python、FastAPI、SQLite、Jinja2 和轻量页面交互。用户通过本机浏览器查看每天上午 9 点生成的中文简报，每日最多 10 条，少则少报，不凑数。

目标是避免漏掉重要消息。新闻涵盖国内外 AI 产品、模型、重要 API 与价格变化；GitHub 侧主动发现近期受到关注的 AI 项目，以近期热度为主要依据。

采集 Hacker News、TLDR AI、TLDR 科技主刊，并用官方来源补充及核验。国内包含机器之心、量子位、新智元，额外候选为 AI科技评论、极客公园和 InfoQ。逐一核对准确身份、渠道和接入状态，不把官网采集描述为公众号完整覆盖。

云端模型由用户提供 API Key。第一版验证一条支持工具调用的兼容接口，记录测试过的实际模型；不要假定修改 Base URL 就能兼容所有服务。当前不设固定模型费用预算，先记录使用量，再依据实际试运行确定上限。

> 入口只校验一次，拒绝重复判空和滥用try/catch；单次逻辑不乱抽函数，低概率防御先征求同意

必须保留并遵守以上原文。执行解释如下：

- 在配置、外部 HTTP 输入、外部内容和模型工具参数进入各自信任边界时校验一次；通过校验的数据在内部直接使用明确类型，避免层层重复判断。

## Agent 行为

采用单个编辑 Agent，提供 read_article、read_repository、find_related_evidence、read_previous_coverage 等有限只读工具。程序负责采集、去重、计时、持久化和结果校验；模型负责按需查证、主题判断、语义合并、入选和中文表述。

工具只读取已登记候选或已配置来源，不运行仓库代码，不读取密钥，不执行网页中的指令。默认每日最多 40 个候选、6 轮模型交互、12 次工具调用。输出引用真实来源 ID，由程序关联 URL。证据不够时减少条目。

GitHub 保存 Star 数和采样时间。存在历史快照时计算实际观测窗口内的净增，展示窗口；没有历史时明确标记首次观察，依据当前 HN、TLDR 或经验证的 Trending 信号，不编造日增 Star。

## 运行与来源要求

时区为 Asia/Hong_Kong。运行期间每小时增量采集，每日 09:00 采集后生成简报。晚启动且当天没有成功简报时补一份；离线多天只补最新一份，默认最多回溯 72 小时，并说明覆盖缺口。手动与定时并发触发合并；手动重生成保留同日修订记录。

优先免费可公开获取的数据。公众号逐个验证官方入口、同媒体官网和可用免费订阅桥接。未接通的账号明确标记，必要时支持手动添加文章链接。不自动购买第三方服务、不索取个人微信登录、不静默降低需求。

新来源可添加为 RSS、已适配站点或待适配网页。GitHub 的主动发现由主题查询和外部候选链接实现，不只追踪固定仓库。来源失败与没有新内容分开表示。

默认监听 127.0.0.1。密钥只保存在本机配置或环境中，屏蔽日志与前端返回中的完整密钥。运行数据和第三方全文不进入版本库。执行这些明确的外部边界要求，不扩展为未经同意的通用安全框架。

## 开发顺序

1. 阅读已确认方案和项目指令，先创建 Conda 环境，再验证依赖与真实来源，形成来源状态表；不提前调用真实模型。
2. 实现采集、存储、去重、GitHub 项目发现和快照。
3. 实现模型接入模板、工具与结构化输出适配代码；提供标记清楚的规则预览以验证本地流程。
4. 实现网页、设置、任务进度、调度与补生成。
5. 运行关键测试和 Windows 实际操作验收，整理 README、演示数据、截图和已知限制。本地运行通过后，再在用户提供实际模型配置的条件下进行真实 API 接入验证；未配置时明确保持待测试状态。
6. 用户审阅实现并确认远程仓库设置及授权后，再创建 GitHub 仓库、推送并验证。

## 验证与交付

测试覆盖解析、时间窗口、去重、热度差值、结构化输出、来源缺失、任务去重和密钥不泄漏等重要行为。默认 CI 使用固定样例，不进行付费模型调用。不要为低影响格式或镜像实现编写测试。

真实模型、真实来源与模拟结果分别标记；未通过的验收不能写成完成。对公众号缺口和模型兼容限制给出具体状态。对每阶段报告做了什么、验证结果和实际剩余工作。

以让其他人能按文档运行且理解数据依据为交付目标。不要提前引入多 Agent、向量数据库、独立前端构建系统、消息队列或部署集群。遇到阻碍先完成不受影响的已授权工作，再就确实需要的选择向用户说明。
